**Goal:** build a systray component that shows how many service orders are open, keeps
a clock ticking, and refetches on demand, then understand exactly how the code got from
your addon into the browser. · **Time:** ~2 h · **Checkpoint:** `code/checkpoints/ch39`

## Why this matters

Everything you have built so far runs on the server. Views are XML the server sends,
reports are HTML the server renders, controllers are Python the server executes.

But the thing your users stare at all day, the Odoo web client, is a JavaScript
application. When a ticket says "this list needs a button that does X without
reloading", no amount of Python will get you there.

Odoo's frontend framework is **OWL** (the Odoo Web Library), and it is small on
purpose. Four pieces: components, a reactive state object (change it and the screen
redraws itself), a handful of lifecycle hooks (functions OWL calls at fixed moments,
such as "just before this first appears"), and QWeb templates written in XML.

If you have used React or Vue you will recognise the shape at once, and the templates
are XML rather than JSX. If you have not, there is genuinely less to learn here than
in either.

The part that surprises people is not OWL itself. It is the delivery: writing a
perfect component does nothing at all until it is listed in an **assets bundle**, and
the failure mode when you get that wrong is silence, not an error. So this chapter
spends as much time on the manifest as on the JavaScript.

Here is the picture to carry in. **The browser has never heard of your addons folder.**
It cannot ask for `librefleet/static/src/workshop_clock/workshop_clock.js`, because it
has no idea that path exists. All it can do is ask the server for a few big, pre-packed
boxes, by name.

Your manifest's `"assets"` key is the packing list: which of your files go into which
box. Leave a file off and the box still ships, perfectly formed, without your code in
it. Nothing errors, because nobody asked for a file they never knew existed. That is why
"my JavaScript is not loading" is a manifest question before it is ever a JavaScript
question.

## Concepts

### A component is a class, a template, and a setup method

```js
import { Component, useState } from "@odoo/owl";

export class WorkshopClock extends Component {
    static template = "librefleet.WorkshopClock";
    static props = {};

    setup() {
        this.state = useState({ openOrders: 0 });
    }
}
```

Three things carry the weight:

- **`static template`** names a QWeb template by string. It is *not* a file path, and
  nothing checks it at build time. The template must be registered under exactly that
  name, or the component throws at render time.
- **`static props = {}`** declares this component takes no props (the values a parent
  hands down into a component). OWL validates props in dev mode, and an empty
  declaration is how you say "none on purpose" rather than "I forgot".
- **`setup()`** replaces the constructor. It runs once per component instance and is
  the only place hooks may be called.

### `useState` is the whole reactivity story

`useState(obj)` returns a Proxy around `obj`. A **Proxy** is a plain JavaScript object
that wraps another one and gets told about every read and every write passing through
it. No magic, just a middleman that notices.

That is the whole trick. Reading a key inside a template subscribes that render to the
key. Assigning to the key marks the component dirty and schedules a re-render. It also
explains the most common beginner bug in OWL:

```js
this.count = 0;              // a plain property, invisible to rendering
this.state = useState({ count: 0 });   // reactive
```

Assigning `this.count = 5` updates the value and changes nothing on screen, with no
error, because nothing was ever watching it.

### Lifecycle hooks: the two that matter today

<Mermaid label="An OWL component's lifecycle: setup runs first and registers hooks, onWillStart runs async before the first render, then the component renders and mounts, and onWillUnmount runs cleanup when it is destroyed." chart={`flowchart TD
    Setup["setup()<br/>register hooks, build state"] --> WillStart["onWillStart<br/>(async, before first render)"]
    WillStart --> Render["first render"]
    Render --> Mounted["onMounted<br/>(DOM exists now)"]
    Mounted --> Live["component is live,<br/>state changes re-render"]
    Live --> Unmount["onWillUnmount<br/>(clean up timers, listeners)"]
`} />

`onWillStart` takes an async callback and OWL waits for it before the first render.
That is how you fetch data without the component flashing a wrong value first.
`onWillUnmount` is where anything you started has to be stopped, most obviously
timers: a `setInterval` outlives its component unless you clear it.

### Assets bundles: the manifest key that makes any of this load

Back to the boxes, with the real name on them. A **bundle** is one of those named boxes: a
list of files Odoo concatenates, minifies, and serves at a single URL. Where your file sits
on disk has nothing to do with whether it gets into one. The manifest decides:

```python
"assets": {
    "web.assets_backend": [
        "librefleet/static/src/**/*.js",
        "librefleet/static/src/**/*.xml",
    ],
},
```

`"assets"` is a **top-level manifest key, a sibling of `"data"`**, never a member of
it. The bundle name decides *where* the code loads, so keep these three straight:

| Bundle | What it is |
|---|---|
| `web.assets_backend` | the web client's box, where this chapter's component belongs |
| `web.assets_frontend` | the public website's box, chapter 37's portal pages |
| `web.assets_web` | the box the browser actually downloads |

That third row is the wrinkle to know before you go hunting in devtools. You declare
into `web.assets_backend`, but the file the browser downloads is `web.assets_web`. Core
defines it as `('include', 'web.assets_backend')` plus a couple of entry points. Three
lines in `web/__manifest__.py`, worth reading once so the nesting stops being abstract:

```python
'web.assets_web': [
    ('include', 'web.assets_backend'),
    'web/static/src/main.js',
    'web/static/src/start.js',
],
```

A box packed inside a bigger box. That is why searching devtools for the name you wrote
in your own manifest comes up empty.

### Registries: how Odoo finds your component

Odoo does not scan for components. You add yours to a **registry**, a global keyed
map the web client reads at startup:

```js
registry.category("systray").add("librefleet.WorkshopClock", workshopClockItem, {
    sequence: 1,
});
```

The `systray` category is the cluster of icons at the top right of the web client.
`sequence` orders items within it. Other categories exist for view types, field
widgets (chapter 40's subject), client actions (chapter 41's), and more.

## Hands-on

<Steps>

<Step>
### Create the component

Odoo's convention is `static/src/<feature>/`, one folder per feature, JS and XML side
by side:

```console
$ mkdir -p addons/librefleet/static/src/workshop_clock
```

```js title="addons/librefleet/static/src/workshop_clock/workshop_clock.js"
import { Component, onWillStart, onWillUnmount, useState } from "@odoo/owl";
import { registry } from "@web/core/registry";
import { useService } from "@web/core/utils/hooks";

export class WorkshopClock extends Component {
    static template = "librefleet.WorkshopClock";
    static props = {};

    setup() {
        // useState wraps the object in a Proxy: assigning to any key on
        // this.state re-renders the component. A plain `this.count = 0`
        // would update the value and change nothing on screen.
        this.state = useState({ openOrders: 0, now: this.formatNow() });
        this.orm = useService("orm");

        // onWillStart is async and runs BEFORE the first render, so the
        // component never flashes a wrong number on its way to the right one.
        onWillStart(async () => {
            this.state.openOrders = await this.countOpenOrders();
        });

        this.timer = setInterval(() => {
            this.state.now = this.formatNow();
        }, 1000);
        // Without this the interval keeps firing after the component is gone,
        // writing to a dead state object forever. Every setInterval in a
        // component needs its matching onWillUnmount.
        onWillUnmount(() => clearInterval(this.timer));
    }

    formatNow() {
        return new Date().toLocaleTimeString();
    }

    countOpenOrders() {
        return this.orm.searchCount("librefleet.service.order", [
            ["stage", "not in", ["done", "cancelled"]],
        ]);
    }

    async onRefresh() {
        this.state.openOrders = await this.countOpenOrders();
    }
}

export const workshopClockItem = { Component: WorkshopClock };

registry.category("systray").add("librefleet.WorkshopClock", workshopClockItem, {
    sequence: 1,
});
```

`useService("orm")` is how a component talks to the ORM. It goes through the user's
session, so **access rights and record rules still apply**: this is not a back door
around chapter 10's security, it is the same server-side check reached from a
different direction.

Note the import paths. `@odoo/owl` is the framework itself; `@web/...` is Odoo's own
web module. Neither is a relative path, both are resolved by Odoo's module system at
bundle time.
</Step>

<Step>
### Write the template

```xml title="addons/librefleet/static/src/workshop_clock/workshop_clock.xml"
<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">

    <t t-name="librefleet.WorkshopClock">
        <div class="o_librefleet_clock d-flex align-items-center gap-2 px-2">
            <span class="badge text-bg-warning" t-out="state.openOrders"/>
            <span class="d-none d-md-inline" t-out="state.now"/>
            <button class="btn btn-link p-0" t-on-click="onRefresh" title="Refresh open order count">
                <i class="fa fa-refresh"/>
            </button>
        </div>
    </t>

</templates>
```

The `t-name` **must match `static template` exactly**. This is the single most common
OWL mistake and the break-it lab at the end makes you feel it.

Everything inside the template reads from the component instance directly, so
`state.openOrders` is `this.state.openOrders` and `t-on-click="onRefresh"` binds
`this.onRefresh`. `t-out` is the same directive chapter 36 used in a PDF report,
doing the same job here.

<Callout type="warn" title="Gotcha">
  `text-bg-warning`, not `text-bg-primary`. Odoo's brand purple *is* the Bootstrap
  primary colour, so a primary badge sitting on the purple navbar renders as
  invisible-background plain text. Verified by looking at it, which is the only way
  this class of bug ever gets caught.
</Callout>
</Step>

### Prove the count is live, not baked in

A count that is correct on page load could just as easily have been rendered once by the
server and frozen. To show it is genuinely live, create an order from the shell *without

```console
$ docker compose exec -T odoo odoo shell -c /etc/odoo/odoo.conf -d tutorial --no-http
>>> v = env["librefleet.vehicle"].search([("license_plate", "=", "SHELL-001")], limit=1)
>>> st = env["librefleet.service.type"].search([], limit=1)
>>> o = env["librefleet.service.order"].create({
...     "vehicle_id": v.id, "service_type_id": st.id,
...     "scheduled_start": "2026-12-01 09:00:00",
...     "scheduled_end": "2026-12-01 10:00:00"})

>>> env["librefleet.service.order"].search_count([("stage", "not in", ["done", "cancelled"])])
```

The badge still reads 1. Click the refresh icon and it becomes 2, with no page reload:

<Step>
### Break-it lab: the template name typo

Change the `t-name` in the XML to something slightly wrong, `librefleet.WorkshopClok`,
and reload the browser. The systray item vanishes. There is no server error, no
failed upgrade, nothing in the Odoo log. Open the browser console (F12):

```text
OwlError: Missing template: "librefleet.WorkshopClock" (for component "WorkshopClock")
    at App.getTemplate (.../web.assets_web.min.js:1008:7)
    at new ComponentNode (.../web.assets_web.min.js:851:133)
```

Read that first line twice. It names `WorkshopClock`, spelled correctly, which is not
what you typed. The error reports what the component **asked for**, not what it found:
your component still requests the correct name, and nothing exists under that name any
more. Errors of this shape name the missing thing, never the typo that made it missing,
so grepping your own code for the string in the error finds it immediately.

This is also the chapter's real lesson about where frontend errors live. Every failure
since chapter 8 announced itself in the terminal; this one only exists in the browser.
**The console is now part of your debugging loop.** Put the `t-name` back before moving
on.
</Step>

## Gotchas

- **`"assets"` is a sibling of `"data"`, not an entry inside it.** Putting asset paths
  in the `"data"` list makes Odoo try to load your `.js` as an XML data file. Putting
  the `"assets"` dict inside `"data"` is worse: the module upgrades cleanly and
  nothing whatsoever loads.
- **The template name is a string with no compile-time check.** A typo in either
  `static template` or `t-name` produces `OwlError: Missing template` in the browser
  console and total silence everywhere else.
- **Assets do not rebuild on module upgrade.** They rebuild when the web client next
  asks for a bundle hash Odoo has not cached. If your change is not showing up, reload
  the browser (and check the network tab is not serving you a cached bundle) before
  suspecting your code.
- **`this.foo = x` is not reactive; `this.state.foo = x` is.** Only values reached
  through the `useState` Proxy trigger re-renders, and getting this wrong fails
  silently rather than loudly.
- **Every `setInterval` needs an `onWillUnmount`.** A timer that outlives its
  component keeps firing forever, writing into a state object nothing is rendering,
  and on a long-lived page they accumulate.
