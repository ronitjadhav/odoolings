**Goal:** change how Odoo picks, stores or prints stock without copying its code, and
know when someone already wrote it. · **Time:** ~3 h · **Checkpoint:**
`code/checkpoints/inv14` (`librefleet_stock` 19.0.1.1.0). It continues the `warehouse`
database.

## Why this matters

Every project asks for something Inventory does not do out of the box. "Take the
half-empty box first." "Put pallets of this brand on that aisle." "Print the vehicle on
the delivery note." The wrong answer copies a 200-line method and changes one line: it
breaks at the next upgrade. The right answer finds the small method Odoo calls for
exactly that decision, overrides it with `super()`, and adds a few lines.

This chapter maps those methods, then uses two of them on LibreFleet: a removal strategy
of your own, and a delivery slip that names the vehicle the parts went into.

## Concepts

### Override the decision, not the process

Odoo's stock code is built from small methods that each answer one question. Override
the one that answers yours, call `super()` for every other case, and the rest of the
process keeps working, upgrades included.

| Question | Method to override | Model |
|---|---|---|
| Where does it go? | `_get_putaway_strategy(product, quantity, package, packaging, additional_qty)` | `stock.location` |
| Which units leave first? | `_get_removal_strategy(product, location)` and `_get_removal_strategy_order(strategy)` | `stock.quant` |
| How much can be reserved? | `_get_available_quantity(...)`, `_get_reserve_quantity(...)` | `stock.quant` |
| How does a move reserve? | `_update_reserved_quantity(need, location, ...)`, `_should_bypass_reservation()` | `stock.move` |
| What do rules do? | a new `action` value plus `_run_<action>(procurements)` | `stock.rule` |
| What does a move carry? | `_get_custom_move_fields()`, `_prepare_procurement_values()` | `stock.rule`, `stock.move` |
| Does it post an entry? | `_should_create_account_move()` | `stock.move` (stock_account) |

### Where things go: putaway

`stock.location._get_putaway_strategy()` returns the location a product should be put
away to, after the putaway rules of chapter 9. Override it for a rule the screen cannot
express, such as "the emptiest shelf", and call `super()` when your rule has no answer.

### Which units leave first: removal

`stock.quant._get_removal_strategy()` finds the strategy: the product category's **Force
Removal Strategy**, else the location's, else its parents', else FIFO (chapter 9). It
returns the strategy's `method`. `_get_removal_strategy_order()` turns that word into the
SQL order `_gather()` sorts quants by:

| `method` | Order |
|---|---|
| `fifo`, `least_packages` | oldest `in_date` first |
| `lifo` | newest first |
| `closest` | then sorted by location name |
| anything else | "Removal strategy ... not implemented" |

A strategy of your own is a `product.removal` record with a new `method`, and one
override that answers for it. Least Packages also changes the search itself
(`_run_least_packages_removal_strategy_astar`), which is how you would go further.

### New rule actions

A rule's **Action** is a selection. `purchase_stock` adds Buy, `mrp` adds Manufacture,
each with `selection_add` on `action` and a `_run_buy` or `_run_manufacture` method that
`stock.rule.run()` finds by name. A module of your own does the same for, say, "Rent from
a partner".

### Reservation

`_get_available_quantity()` says what may be reserved, `_get_reserve_quantity()` which
quants and how much of each, and `stock.move._update_reserved_quantity()` turns that
into move lines. `_should_bypass_reservation()` is true for moves that never reserve:
from a vendor, customer, inventory or production location, or of a product that does not
track inventory. Override them to forbid a lot, an owner
or a location for some moves; OCA's `stock_owner_restriction` and `stock_restrict_lot`
are examples.

### Reports

Delivery slips and picking operations are QWeb templates: `stock.report_delivery_document`
and `stock.report_picking`. Extend them with `inherit_id` and an `xpath` or a `name`
anchor, never a copy. Show a report as a page with `/report/html/<report>/<id>`.

### Context keys you will meet

| Key | Effect |
|---|---|
| `inventory_mode` | lets code write the counted quantity on quants (chapter 10) |
| `skip_backorder` | validates without opening the backorder dialog |
| `picking_ids_not_to_backorder` | validates those transfers without a backorder |
| `cancel_backorder` | cancels what is not done instead of creating a backorder |
| `location`, `warehouse_id`, `strict`, `lot_id`, `owner_id`, `package_id`, `from_date`, `to_date` | quantity computations (chapter 13) |

### Check OCA before you write

The Odoo Community Association keeps three repositories of stock modules. A few worth
knowing, all on the 19.0 branch today:

| Repository | Module | What it adds |
|---|---|---|
| stock-logistics-warehouse | `stock_inventory` | inventory adjustment documents that group counts |
| | `stock_move_location` | move everything in a location to another in one go |
| | `stock_putaway_product_template` | putaway rules for all variants of a product |
| | `stock_warehouse_calendar` | a working calendar per warehouse for lead times |
| stock-logistics-workflow | `stock_no_negative` | forbids negative stock |

The one decision it changes:

```python title="addons/librefleet_stock/models/stock_quant.py"
from odoo import models


class StockQuant(models.Model):
    _inherit = "stock.quant"

    def _get_removal_strategy_order(self, removal_strategy):
        if removal_strategy == "smallest_first":
            # empty the nearly empty bins first, oldest among equals
            return "quantity ASC, in_date ASC, id"
        return super()._get_removal_strategy_order(removal_strategy)
```

Import it in `models/__init__.py` (`from . import stock_quant`), and in the manifest add
`data/product_removal.xml` and `report/report_deliveryslip.xml` (next step) to `data`
and bump the version: a change to data files needs an upgrade, and the version says so.

## Gotchas

- **Always call `super()` for the cases you do not handle.** The removal override answers
  for one method and passes every other strategy on. Without it, FIFO, LIFO and the rest
  stop working.
- **Data needs an upgrade.** A new XML record or template only reaches the database with
  `-u` or Apps → Upgrade, and the version bump is how others see that they need one.
- **Anchor on names, not positions.** `div name="div_origin"` survives Odoo's layout
  changes; an xpath like `//div[3]` breaks at the next release.
- **The removal order is SQL.** `_get_removal_strategy_order` returns an `order` for a
  search on quants, so it may only use stored quant fields.
- **A category strategy beats the location's.** Force Removal Strategy on the category
  wins over the one on the location, so a location rule seems ignored once a category
  has one.
- **Look at OCA's 18.0 branch too.** A module missing on 19.0 may be one migration away,
  and helping migrate it costs less than writing your own.
