**Goal:** keep the numbers in Odoo equal to what is really on the shelves, and pick
several orders in one walk. · **Time:** ~3 h · **Checkpoint:** none, this chapter writes
no module. It continues the `warehouse` database and installs Batch, Wave & Cluster
Transfers.

## Why this matters

Every number in Odoo is a claim. A bottle breaks, a box is put on the wrong shelf, a
picker grabs two instead of one, and the claim drifts away from the shelf. Counting is how
you pull it back: someone looks, writes down what is there, and Odoo moves the difference
to a virtual location so the books balance.

Then there is the walking. Two orders that need things from the same shelf should not
cost two trips. Odoo's batches put several transfers into one job.

This chapter counts the depot properly, including a count that a scrap makes stale while
it waits. It undoes a count that turned out wrong, relocates stock, sets up recurring
counts, and batches two customers' picks into one.

## Concepts

### Counting is writing on quants

**Inventory → Operations → Physical Inventory** lists every quant with its **On Hand**.
A count is two fields on the quant itself: **Counted** (`inventory_quantity`) and the
**Difference** it computes against On Hand. Nothing moves until you **Apply**. Then Odoo
writes one move per counted quant, between the shelf and **Inventory adjustment**, the
virtual location that absorbs gains and losses, and the count fields clear again.

| Button | What it does |
|---|---|
| **Apply** on a row | applies that count at once, reference "Product Quantity Updated" |
| **Apply** with rows selected, or **Apply All** | asks for an **Inventory Reason** and a **Counting Date**, then applies them together |
| **Clear** | forgets the count |
| **Request a Count** | schedules the selected quants for a date and a person |
| **Actions → Set to quantity on hand** / **Set to 0** | fills Counted for you |
| **Actions → Relocate** | moves the stock elsewhere straight away, with a reason |
| **Print** | the **Count Sheet**, a paper list to count from |
| **History** | the done moves of that quant, where a count can be reverted |

### Stale counts and conflicts

A count is taken at one moment. If stock moves between the count and the Apply, the
row turns orange (**is_outdated**): the Difference no longer matches. Apply then asks:

- **Keep Counted Quantity**: trust the number you wrote; the Difference is recomputed.
- **Keep Difference**: trust the gap you found; Counted shifts by what moved since.

### When to count

Each quant shows a **Scheduled** date, the next time it should be counted. Two settings
feed it: the company's **Annual Inventory Day and Month** (Settings, Operations; 31
December by default) and a location's **Inventory Frequency** in days, which counts it
again that many days after its **Last Inventory**. The earlier date wins.

### Scrap

A **scrap** (`stock.scrap`) takes stock out of a location for good: the product, a
quantity, a lot or package if it has one, a **Scrap Reason** tag and a source document. In
Odoo 19 it goes to the same virtual location as counts, **Inventory adjustment**.
**Replenish Quantities** asks the replenishment rules to buy or make the scrapped amount
again. A product can send its counts and scraps elsewhere through its **Inventory
Location** (developer mode, the product's Inventory tab, Counterpart Locations).

### Batches and waves

The **Batch, Wave & Cluster Transfers** setting installs `stock_picking_batch`:

- A **batch** groups whole transfers into one job (`BATCH/...`), validated in one click.
  Make one by hand from the transfers list (**Actions → Add to batch**), or let an
  operation type do it: **Automatic Batches**, grouped by **Contact**, **Destination
  Country**, **Source Location** or **Destination Location**, with **Maximum lines** and
  **Maximum transfers** per batch and **Auto-confirm**.
- A **wave** groups move lines from several transfers, split by **Product**, **Product
  Category** or **Location** (**Actions → Add to wave**, or the Wave Grouping options).
- **Cluster picking** is a batch picked straight into one container per order, so the
  goods are sorted while they are picked; it needs Packages as well.

The **Dispatch Management System** setting (`stock_fleet`) plans which vehicle carries
which batch; it is named here only.

## Gotchas

- **A row's Apply does not ask for a reason.** It applies at once, under "Product
  Quantity Updated". To name a count, select the rows and use the header Apply or Apply
  All.
- **Counts go stale.** Any move between counting and applying makes the Difference
  wrong. Apply soon after counting, and read the conflict choices: Keep Counted Quantity
  can quietly undo a scrap or a pick.
- **Show Expected Quantity is global.** The box in Request a Count is stored as one
  company-wide parameter, not per request: switching it on for one count shows On Hand on
  every count.
- **Scrap and counts share one location.** In Odoo 19 both go to Inventory adjustment, so
  reports that need scrap apart must filter on the scrap orders, not on the location.
- **Automatic Batches needs a grouping.** Ticked alone, it batches nothing.
- **A batch of one is still a batch.** The first transfer creates a batch on its own and
  waits for a match, so the Batch Transfers list shows batches holding a single pick.
